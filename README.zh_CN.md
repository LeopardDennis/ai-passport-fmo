# AI Passport FMO 实时通联显示器

这套固件把 FoloToy AI Passport 变成一块常驻的 FMO（NFM Over Internet）状态屏。它会显示当前选择的 FMO 频道、正在发言的呼号、空闲时的最近发言呼号，以及最近三次通联记录、连接状态和电池电量。

## 工作方式

显示器使用 FMO 设备提供的局域网网页接口：

- `ws://<host>:<port>/events` 提供 `qso/callsign` 事件，其中包括 `callsign`、`isSpeaking`、`isHost` 和可选的 `grid`／`crossServer` 字段；
- `ws://<host>:<port>/ws` 定期接收 `station/getCurrent` 请求，让屏幕显示当前选择的频道。
- `/events` 的 `qso/history` 推送近期呼号及 UTC 时间，黄框显示最新三次记录，不查询已保存日志详情。

音频连接 `ws://<host>:<port>/audio` 用于接收通联对话。已启用的 WebSocket 都会自动重连。固件只观察 FMO 的局域网接口，不会模拟 FMO 电台，也不会直接连接 FMO MQTT 服务器，因此无需把 FMO 设备证书或私钥复制到 AI Passport。

## 配置

竖屏界面参考所提供的 FMO 图片使用黑、橙、白配色（非官方色值规范）。中央大呼号是
当前发言人：普通发言使用橙色粗体，跨服务器标记 `crossServer` 为 true／1 时使用红色粗体，
结束后以白色粗体保留上次呼号。
大呼号后显示灰色小字网格码，结束发言后保留，直到下一位发言者出现；缺失网格时隐藏。不显示“几秒前”或电台／本机前缀。底部细黄色条显示送往播放的通联 PCM
音频 RMS 强度，快速上升、平滑回落。它反映原始对话声音，独立于扬声器音量；关闭音频、
断线或进入配网／菜单时清空。微弱输入被过滤，缺少音频时不显示；它不是射频信号测量值。
不模拟未知数据。
呼号使用 Montserrat Bold，配网密码使用内置常规字重，中文频道使用 Noto Sans CJK，
不宣称与 FMO 原厂字体完全一致。
状态和操作提示使用中文，呼号、网络名称及地址保持原样。iOS 风格电池图标内显示百分比
数字，20% 及以下变红，无法读取时显示空轮廓，不猜测充电状态。频道与呼号按可见字形
上下居中，长呼号和配网密码缩小字号后也保持居中。

黄框标题为 `QSO`，显示 FMO 推送的最近三次通联，最新记录在上。每条记录分为两行：
上行为白色粗体呼号，下行为常规字重的灰色北京时间（`YYYY-MM-DD HH:MM:SS`）。
相同呼号在不同时间发言仍保留为独立记录，缺失行／时间使用占位。
只有收到 `qso/history` 推送时才更新，不覆盖实时发言人、PTT 状态或频道查询归属。
Wi-Fi／事件连接丢失时清空历史，控制查询延迟不清空。
该历史接口没有每条记录的频率、模式、备注和网格码；不为这些行查询已保存 QSO 详情，
也不使用本机 `config/getUserPhy*` 配置。通联状态、大呼号和黄色音频强度条仍在黄框上方；
发言时显示“正在发言”，结束后显示“上次通联”。当前网格码以灰色小字显示在大呼号后，
结束发言后保留到下一位发言者出现；长呼号在预留宽度内滚动，不与网格码重叠。

顶部 FMO 与电量之间显示北京时间（UTC+8），格式为 `HH:MM`。Wi-Fi 联网后通过
`pool.ntp.org` 非阻塞校时；系统时间有效前显示 `--:--`。重连后重新启动同步，
不重复分配服务。已校准的时钟在暂时断网期间继续运行，熄屏唤醒时重绘当前分钟。
自动校时需要能够访问 NTP 服务器。界面不显示独立收发频率。

FMO 事件与控制连接就绪后自动播放通联对话，默认音量 50%。`/audio` 提供
8 kHz、16 位有符号小端、单声道 PCM，通过现有 ES8311／I2S 驱动在独立任务中播放。
固定 8 KiB 队列处理 WebSocket 分块、短暂缓冲及缺音补零；积压时丢弃最旧完整采样，
限制延迟。关闭音频或断线会清空缓存并关闭音频连接；恢复播放前用静音数据替换 DMA
中的残留声音，再接收新数据。熄屏仍可播放。不增加麦克风采集、录音或发射／PTT 指令。
底部一行居中显示“音频: 50%  长按OK: 配网”：开启时显示当前音量，关闭时显示 0%，不显示开／关文字；短按 OK 仍开关音频。无人发言且已有通联时，
中间显示“上次通联”和白色粗体呼号；首次通联前显示“--”及“等待电台发言”。运行时音量／开关重启后复位，`CONFIG_FMO_VOLUME` 设置初始音量。
音频或解码芯片故障不影响守听显示。实际声音、音频与显示并行时的内存／栈余量和端到端
延迟仍需真机验证。接口另见 [FMO 网页客户端 API 文档](https://github.com/niufox/fmo-mobile-controller/blob/main/API_DOCUMENTATION_v2.md)。

```bash
cmake -S tests/ui_preview -B /tmp/fmo-ui-preview
cmake --build /tmp/fmo-ui-preview
ctest --test-dir /tmp/fmo-ui-preview --output-on-failure
/tmp/fmo-ui-preview/fmo_ui_preview onair /tmp/fmo-onair.ppm
```

其他预览状态：`idle`、`muted`、`lastheard`、`offline`、`setup`（扫码）、
`setup_info`（热点信息）、`network`、`long`、`rare`、`error`，以及
`meter_low`／`meter_mid`／`meter_high`（音频强度）。

最多保存五组验证成功的 Wi-Fi，自动导入旧版单网络配置。相同 SSID 的密码只有在新连接
成功后才更新；第六个不同网络会被拒绝，需要先删除一个。配网页面只显示已保存名称，
不返回密码，删除前有确认，并提供不添加网络直接完成的按钮。删除全部网络后保留配网
入口，不会恢复旧版凭据。一次配网结束后，可从网络菜单再次进入配网添加其他网络。

开机优先尝试上次成功的网络。断线后，每次连接最多等待 25 秒，再按扫描信号强度尝试
其他已保存网络；未扫描到或隐藏网络也会尝试。全部失败后等待 30 秒再开始下一轮。
正常联网时不会为了更强信号或因为 FMO 不可用而换网。Wi-Fi 断线会关闭旧 FMO 连接，
联网后为新局域网重新创建连接；新网络中也需要能访问 FMO。只有首选网络改变时才写入
NVS，不会每次重连都写 Flash。支持 WPA2 及以上个人网络和开放网络，不支持企业认证。

无预置凭据的固件首次启动会开启加密热点，并显示连接二维码。用手机相机扫码加入
热点；若无法扫码，短按 **OK** 查看 `FMO-Setup-XXXX` 和随机热点密码，手动连接。
再短按 **OK** 可回到二维码。即使手机提示没有互联网，
也请保持连接，并手动打开 `http://192.168.9.1`。选择附近的 2.4 GHz Wi-Fi，
或手动输入隐藏网络名称，再填写密码提交。列表在每次进入配网时扫描一次，
连接失败可直接重试。
切换到其他网络重试时，配网热点可能短暂断开；若网页失去响应，用屏幕上的密码
重新连接热点即可。

固件最多等待 25 秒验证 Wi-Fi 和 DHCP，成功后才保存到独立的 `fmo_wifi`
NVS 命名空间；失败时不会主动删除原有凭据。成功后关闭热点及网页服务，
连接已保存的 FMO 地址（默认通过 mDNS 解析 `fmo.local:80`）。两台设备需要处于允许组播和设备互访的局域网。

配网页的 **FMO 地址** 可保存主机名或 IPv4 地址和端口，默认 `fmo.local:80`。
设备保存的地址优先于编译期配置，完成配网后生效；不需要重新编译。
**检查端口** 会使用已保存的 Wi-Fi 检查地址解析和 TCP 端口。若还没有已保存网络，
先完成 Wi-Fi 配网，再进入配网检查。端口可达不代表 WebSocket 路径或事件字段兼容，
最终 FMO 接口状态以设备守听页为准。检查不会保存新 Wi-Fi 凭据或更改已保存的 FMO 地址。

网络或配网服务启动失败时，后台每 5 秒重试；网络菜单中的重试可立即结束等待。
失败的初始化会注销事件处理器并释放 Wi-Fi 资源，成功恢复后清除错误提示。
安装数据清理失败时仍禁止联网，后台继续重试清理，保留身份和 Recovery。

正常运行时长按 **OK** 打开网络菜单，上下键选择，短按 **OK** 执行：
**Wi-Fi 配网**（重启进入扫码页）、**重连 Wi-Fi**（立即重试已保存的网络）、
**返回守听**。长按 **OK** 返回。配网排在重连上方，旧路由器不可用时也能进入。
配网期间长按 **OK** 取消，关闭热点并恢复已保存网络，不保存尚未验证的新密码。
已在网页删除的网络不会因取消而恢复；新连接成功前保留旧配置。正常联网时点击
重连不会强制断开。配网服务启动失败会自动重试，也可从网络菜单立即重试。
本版本不提供自动弹出的认证门户，也不假定其他 Passport 固件的密码可以共享。
网页只允许从配网热点访问，提交使用随机会话令牌，不会返回已保存的 Wi-Fi 密码。
凭据保存在普通 NVS 中，未启用加密存储。

高级用户仍可通过 `idf.py menuconfig` → **FMO Live Monitor** 设置编译期备用
Wi-Fi、FMO 地址／端口、亮度及初始音量。设备保存的 Wi-Fi 优先；不要公开包含密码的固件。

## 构建和安装

激活 ESP-IDF 5.5.3，然后执行：

```bash
./tools/validate.sh --static
./tools/validate.sh --setup
```

可安装的合并固件为 `build/FoloToy-AI-Passport-full.bin`。必须保留受保护的 `cardid` 和 Recovery 分区。对于已经完成出厂配置的设备，优先使用 AI Passport 小程序安装；不要擦除整片 Flash。

## 安装后清除应用数据

安装完整 FMO 固件后，首次启动清除所有应用数据：Wi-Fi 网络与密码、旧 FMO 配置，
以及 PDKPASS 的赛历、积分、成绩、提醒赛程和开关。同一版本重新刷入也会清除。
正常开关机和长按 OK 重新配网会保留本次安装的数据。设备身份与永久 Recovery 保留。

完整包包含 `fmo_install` 安装重置请求；清理在初始化 NVS 和 Wi-Fi 前完成，
成功后才记录当前固件指纹。中途断电会在下次开机重试，清理失败则不会使用旧数据联网。
保留 `pdk_cache` 分区声明仅用于安全清除旧缓存。请使用完整固件包：只刷应用镜像
会漏写安装重置请求，无法可靠识别同一个二进制镜像的重新安装。

## 按键

- **上键**：通联音量增加 10%，最高 100%。
- **下键**：通联音量降低 10%，最低 0%。
- **确定键**：开启／关闭音频，保留选择的音量。
- **长按上键**：立即刷新当前 FMO 频道（开机持续 5 秒进入 Recovery 的机制保持不变）。
- **长按确定键**：打开网络菜单；菜单中上下选择、短按确定执行、长按返回。
- **配网页短按确定键**：切换二维码与热点信息；长按取消并返回网络菜单。

## 空闲熄屏与唤醒

没有发言或按键操作时，30 秒后背光降至不高于 20%，90 秒后熄屏。LCD 进入面板
休眠并暂停刷新；Wi-Fi、FMO 事件／控制连接、已开启的音频播放和按键扫描继续运行。有效的发言开始事件或
任意按键都会唤醒屏幕。第一下按键仅唤醒，包括长按；再次操作才执行正常按键功能。
持续发言、网络菜单和 Wi-Fi 配网期间保持亮屏。唤醒时先重绘最新状态，再恢复亮度并更新电量。
熄屏期间暂停电量轮询。这是显示省电，不是 MCU 深度休眠；续航提升需要真机测量。

## FMO 兼容性

当前实现依据现有社区 FMO 网页客户端所使用的接口。不同 FMO 固件版本可能修改局域网事件字段或路径。如果屏幕已经连接，但始终没有呼号，请从 FMO 网页接口获取脱敏后的 `/events` JSON，并调整 `main/fmo_network.c` 中的 `parse_fmo_message()`。不要公开 Wi-Fi 密码、FMO Secret、证书、私钥或未经脱敏的日志。

## 仍需进行的真机验证

- 确认 Passport 能连接到预期的 2.4 GHz 网络；
- 确认开机及 FMO 端切换频道后，屏幕显示的频道与 FMO 一致；
- 使用电台按下和释放 PTT，检查正在发言、粗体呼号及上次通联状态切换，灰色网格定位码在发言结束后保留，下一位发言者出现时更新或清空；连接稳定且频道有效时，发言开始、切换呼号和结束都不应显示同步页面；
- 让两台设备在 Wi-Fi 中断后继续运行，确认能够自动重连；
- 确认 30 秒调暗、90 秒熄屏，按键与发言可唤醒，熄屏期间 FMO 连接不中断；
- 在真机上检查 USB 日志、最小剩余堆、最大连续内存和任务栈余量、按键响应、界面裁切和电量显示；
- 对亮屏、调暗、熄屏状态测量电流，再评估轮询频率和任务栈调整；
- 检查保存 FMO 地址、跨网络访问、端口检查和配网启动失败后的菜单重试。


## 可靠性与资源使用

- 网络侧在互斥锁内归并状态，以单槽快照交给界面；即使界面来不及处理每次 PTT 变化，也能收到最终状态。
- 中文频道名按 UTF-8 保留，超长名称只在完整字符边界截断；非法文本回退显示频道 UID。
- 显式 `isSpeaking: false/0` 只结束发言，保留已确认频道和上次通联显示。空、null 或省略呼号时结束当前发言；具名结束通知必须匹配当前呼号。结束通知不使用网格／主机信息，重复通知不会重置上次通联时间。发言开始仍要求有效呼号，并校验可选元数据。
- 非法 JSON、无效呼号或发言开始元数据、原始或 JSON 转义的 NUL 会清除实时发言状态，并重新确认频道。早于新发言的频道响应不会清除新呼号、使已确认频道失效，也不会恢复未经确认的频道。
- 三个 WebSocket 连接每 10 秒发送心跳，允许 30 秒等待 PONG。控制发送与底层读取均允许等待 3 秒；等待频道响应时保留已确认频道，不覆盖未完成查询。日志区分连接故障和协调任务触发的重连原因。
- 配置框四行、发言状态及呼号的位置固定，初次无数据、正在发言与上次通联切换时保持一致。
- 异常断线和正常 CLOSE 握手都会重连。客户端创建失败时，在 Wi-Fi 可用后重试。
- 频道查询超过 10 秒未回复或发送不完整时，重建控制连接并丢弃旧响应；协议没有请求 ID，不在旧连接上覆盖未完成查询。
- 每秒查询频道，新发言也会触发后台确认；已有有效频道时立即显示发言呼号，不切换到同步页面。没有有效频道时仍显示同步。早于新发言的响应会丢弃并重查，保留原有有效频道且不延长确认时间。频道变化时清空旧呼号，频道确认超过 15 秒即失效。
- 局域网通联事件没有频道 UID，两个连接无法提供原子化的频道／发言快照。因此频道归属属于尽力同步：频道切换时清掉无法确定归属的发言，等待后续事件；轮询不能保证瞬时一致。
- 文本组装器支持接收分段、连续帧和穿插控制帧；每个文本连接使用 2 KiB 缓冲，正常的 20 条通联历史列表不会再使当前发言／频道失效。过大或非法帧仍会清除实时发言状态，日志记录连接类型和帧大小，不记录内容。
- 字库构建时无损拆成两段，保留原有全部字形、压缩位图和度量；使用紧凑字形描述降低应用占用，不改变分区。
- 标签内容变化时才更新。未使用的演示源码、BLE 和 LVGL 示例不参与应用构建；Recovery 的 BLE 位于出厂永久固件中。
- 每分钟输出内部堆最低剩余量、最大可分配块、协调任务和 WebSocket 栈余量。电池任务的栈余量以 DEBUG 级别输出。真机测量前保留保守栈大小。

## 验证与安装的区别

无需预置密码的通用安装包使用 `./tools/validate.sh --setup` 构建，仅读取仓库默认配置，
忽略私密的 `sdkconfig`，输出 `build/FoloToy-AI-Passport-full.bin`，安装后使用手机配网。

`./tools/validate.sh` 执行主机检查和**启用完整网络路径的验证构建**，使用
`tests/sdkconfig.network` 中公开的虚拟配置，产物放在
`build/validation/FoloToy-AI-Passport-full.bin`，不能用作实际安装固件，也不会覆盖用户的配置版镜像。

给自己的设备使用时，执行 `idf.py menuconfig`，然后执行
`./tools/validate.sh --configured`。该命令把本地配置复制到私有临时文件，检查配置并生成
`build/FoloToy-AI-Passport-full.bin`。镜像包含 Wi-Fi 配置，不应公开发布；CI 产物只包含虚拟配置。
构建脚本仅在配置的临时副本中关闭 `LV_FONT_FMT_TXT_LARGE`，原配置保留。
直接使用 `idf.py build` 的旧配置须先关闭该选项，与紧凑字库保持一致。

本项目基于 [FoloToy/ai-passport](https://github.com/FoloToy/ai-passport)。
接口参考：[FMO 网页客户端 API](https://github.com/niufox/fmo-mobile-controller/blob/main/API_DOCUMENTATION_v2.md)。
